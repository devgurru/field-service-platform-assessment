npm run test:db
npm run build
npx playwright install chromium

postman spec lint api/payroll-export.openapi.json --issueType syntax --no-report-events --output json
npm audit --omit=dev --audit-level=high

The CSV fixture is independently written, rather than generated by the exporter under test. Git
attributes preserve its literal CRLF bytes. The database test applies the same migration published
in the sample, using a disposable, network-isolated container and test-only Supabase identity
primitives.

## Limits of the evidence

- No hosted Supabase database, Auth service, PostgREST gateway or deployed Edge Function was
  exercised. SQL tests verify real PostgreSQL policy behavior with a minimal `auth.uid()` bootstrap;
  HTTP tests use injected Auth/repository doubles. A hosted end-to-end check remains a separate
  evaluation step.
- The public site is a synthetic Next.js fixture demo. Its role switch demonstrates UI behavior;
  actual access decisions belong to the database/RPC. The optional live adapter is type-checked and
  documented but not exercised against real credentials.
- The client's corrected reference file and full defect specification have not been supplied.
  Passing this sample's fixture does not constitute acceptance of the client's Module 1.
- CRM, n8n, ERPNext, dispatch, operational-domain migrations and audit/approval lifecycles are
  proposed scope, not running integrations in this repository.
- Private reference source was inspected read-only for stack patterns. The public code has fresh
  history and synthetic fixtures. Automated secret/similarity checks supplement provenance review;
  they cannot independently prove arbitrary future files are safe to publish.
